iHow every model is built & evaluated

  • Time-based splits, never random: train on days 1–70, validate 71–80, test 81–90. Random splits leak the future and inflate scores.
  • Scalers and encoders are fit on train only and saved with the model (ml/artifacts/<model>/).
  • Models never train on anomaly_label / anomaly_type — ground truth for evaluation only.
  • Every prediction ships with a reason: SHAP factors, triggering signals, or a rule name.
  • random_state=42 everywhere. Library versions pinned in ml/requirements.txt.

1Unusual behaviour / anomaly detection

Isolation Forest · sklearn · trained by us · v2 · P0

What it does

Scores every telemetry minute per machine for behaviour that no single threshold catches — slow drifts, multi-signal faults — and separates real faults from sensor glitches (one signal extreme for one minute). Glitches become an info event and are forward-filled so they don't pollute features; persistent faults fire a UNUSUAL_BEHAVIOUR warning with the top-3 signals by |z| as the explanation.

Features (40): for each of 12 signals (engine_rpm, engine_load, coolant_temp, oil_pressure, hydraulic_pressure, hydraulic_oil_temp, fuel_rate, battery_voltage, vibration, pitch, roll, ground_speed): 5-min mean, 5-min std, 15-min slope — plus idle_pct_30min, rpm_per_load, fuel_per_load, coolant−hydraulic_oil_temp.

Architecture: one Isolation Forest + StandardScaler per machine type × state (idle/working) = 8 models, trained on settled, pre-failure minutes only (≈335,500 rows across days 1–70).

telemetry → glitch cleaning → trailing windows → state (idle/working) → IsolationForest[type,state] → 3 consecutive flags (5-min settle gate) → machine_fault | sensor_glitch | normal

2Task time estimation

LightGBM quantile regression (p10 / p50 / p90) · trained by us · v1 · P0

What it does

Before a shift, predicts how long each task will take as a realistic range (p10–p90, 80% coverage), explains the estimate in plain language ("Material: rock — +7 min") via SHAP, and compares it with the operator's own pace for that task type (expected_efficiency). Powers shift planning and the plan re-evaluator (model 12).

Features (21): task/material/machine type, unit, quantity, terrain slope, haul distance, operator skill / experience / certification, operator's usual pace for this task type (last 30 days, past-only), machine health at start, weather (temp, rain, wind, visibility, dust), shift type, hours into shift, day of week, operator fatigue-hour average.

Target: log1p(actual_duration_min) on 6,379 completed tasks (split by date: 4,946 / 717 / 716). Intervals are conformalized (CQR on validation, offset ×1.053 in log space) because raw intervals were too narrow out-of-sample (66% → 80% coverage).

3Predictive maintenance

XGBoost classifier · trained by us · v2 + safety floor · P1

What it does

For each machine, every engine hour, predicts the probability of a failure in the next 48 engine hours and names the likely component (cooling / electrical / engine / hydraulics / undercarriage) with the top SHAP factors pushing the risk up. Risk bands: <0.3 low, 0.3–0.6 medium, >0.6 high. Runs live every 10 replay minutes; feeds the digital-twin health score (model 11).

Features: hours since service (+ ratio), 24 h/72 h means & slopes of coolant temp, oil pressure, hydraulic oil temp, hydraulic pressure std, vibration, battery voltage — each signal's 24 h deviation from the machine's own baseline (t−336…t−72 engine h) in σ units, worst deviation/trend across signals, vibration while travelling, anomaly events + mean anomaly score (model 1), fault-code episodes 24 h / 7 d, cumulative high-load hours since service, machine type and age.

Label: 1 if a maintenance_log failure occurs in the next 48 engine hours (failure→repair rows and censored tails dropped). Evaluation uses forward-chaining time CV grouped by failure: 15 held-out failures (the 90-day holdout has only 2).

Safety floor (ships in production): any signal ≥ 6σ off the machine's own normal forces the probability to ≥ 0.35 (medium) so a novel failure mode is never shown as "low".

4Fleet clustering + outliers

K-Means + z-score outliers + PCA / DBSCAN · trained by us · v2 · P1

What it does

Every week, groups operators and machines by behaviour (idle-heavy, efficient, low output, needs safety coaching), computes an efficiency index and ranks entities within their site, and flags outliers for the manager to verify. Powers the manager dashboard scatter plot and the training recommender's "needs safety coaching" trigger.

Features (weekly, per entity × machine type): fuel per productive hour, idle %, productivity per hour, time ratio (actual ÷ fleet p50), anomaly events per 10 engine-h (model 1), safety events per 10 engine-h. Machine types are never mixed — every comparison is within type via type-local z-scores; operators get the weighted mean across the types they drive.

Reliability weighting: operator features are weighted by √ICC (week-to-week reliability: idle 0.98, fuel 0.87, productivity 0.79, time_ratio 0.72, safety 0.26, anomalies 0.07) so Poisson noise in rare events doesn't set cluster boundaries. Machines keep equal weights.

efficiency index = 0.35·z(productivity) − 0.25·z(fuel/h) − 0.20·z(idle%) − 0.20·z(time_ratio)

iiPretrained models, rules & LLM systems

Not trained on our data — configured, prompted, or used off the shelf.

R Alert rule engine (P0)

Instant, explainable warnings for known limits, run on every telemetry minute before the ML models. 11 rules: coolant >100 °C / >105 °C, hydraulic oil >90 / >95 °C, oil pressure <100 kPa (rpm>1200), battery <24 V, hydraulic-pressure-drop leak detector (2-min mean <65% of prior baseline), seatbelt, tip risk (>15° / >25°), excess idle, overspeed (per-type limits: excavator 5.5, dozer 10, loader 20, truck 40 km/h), fault codes.

Graded response for critical internal alerts: warn → derate (2 min) → recommend safe shutdown (5 min or rising) → escalate to manager (7 min or ignored). Never cuts power automatically. Hysteresis: clears only 5% inside the limit for 2 min. 100% recall on all 6 injected anomaly types when combined with model 1 (see model 1 table).

5Fatigue & attention (P0 · pretrained)

Camera pipeline (MediaPipe FaceLandmarker, 478 landmarks) detecting drowsiness, distraction and phone use; drives the in-cab voice assistant and widens proximity zones when fatigue is high.

Parameters: eyes closed if EAR < 0.22 (per-person calibration in first 30 s: 0.75 × open-eye mean); PERCLOS over 60 s; yawn if MAR > 0.6 for >1.5 s; head down if pitch < −20° for >2 s (solvePnP, relative to calibration); phone = YOLO11n COCO class 67, conf ≥ 0.5, every 5th frame.

score = 0.45·min(PERCLOS/0.3,1) + 0.15·min(yawns₁₀/3,1) + 0.15·min(head_down₁₀/3,1) + 0.15·min(hrs/10,1) + 0.10·night → low <0.35 ≤ medium <0.6 ≤ high

Eyes closed >2 s while moving = immediate critical alert. One fatigue_log row per minute.

8Voice assistant (P1 · pretrained)

Push-to-talk. STT: faster-whisper small, int8, auto language, VAD filter. Intent: LLM with 7 functions (next_task, report_incident, machine_status, explain_alert, call_supervisor, sos, ask_training), temperature 0. TTS: Piper (English/Hindi), browser fallback.

9Shift handover summary (P1 · LLM)

Facts from the previous shift (notes, open alerts, safety events, unfinished tasks, fuel, maintenance prediction) → LLM (temperature 0.3) → ≤ 5 labelled lines (Machine / Open issues / Check before starting / Unfinished work / Fuel), stored on shifts. Incident drafts use temperature 0 with a strict JSON schema.

10Training recommender (P1 · rules)

Last-7-day triggers → module topic: idle >25% → fuel-efficient operation; ≥3 harsh maneuvers → smooth controls; time_ratio >1.2 for a task type → technique for that type; ≥2 proximity breaches → blindspot awareness; ≥1 seatbelt violation → cab safety; ≥1 tip risk → slopes; cluster "needs safety coaching" → scenario pack. Max 2 open recommendations per operator, each with a plain-language reason.

11Digital twin health score (P1 · formula)

per subsystem: score = 1 − max(rule_penalty(0 / 0.3 / 0.7), 0.6·anomaly_contrib, failure_prob_if_component) · overall = min(subsystems)

Subsystems: engine, cooling, hydraulics, electrical, undercarriage. Bands: ≥0.75 green, 0.5–0.75 orange, <0.5 red. Snapshot every replay minute. Demo: M04's electrical failure reads green until 23 engine hours out, then drops to 0.32 by the failure.

12Plan re-evaluation (P1)

Triggers: task past its p90, rain >2 mm/h, health <0.6, fatigue high, manager edit. Re-predicts remaining tasks with current conditions, greedy-fits by priority then p50 (with skip), overflow moves to the next shift, and shows a diff for accept/reject. Fatigue high inserts a 15-min break before the next task. Demo: rain mid-shift changed 5 of 15 replanned shifts.
